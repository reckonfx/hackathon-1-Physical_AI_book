# Diagram Creation Workflow: AI-Generated/Open-Source Guidelines

## Purpose
This document outlines the workflow and guidelines for creating diagrams for the Physical AI Book. All diagrams must be either AI-generated or open-source to ensure proper licensing and avoid copyright issues.

## Acceptable Sources

### 1. AI-Generated Diagrams
- Created using AI tools like DALL-E, Midjourney, Stable Diffusion, etc.
- Must be clearly labeled as AI-generated
- Should be customized to match the book's style and requirements

### 2. Open-Source Diagrams
- From repositories with permissive licenses (MIT, Apache 2.0, CC BY, etc.)
- Must include proper attribution to the original creator
- Should be modified as needed to fit the specific content

### 3. Custom Created Diagrams
- Created specifically for this book using open-source tools
- Licensed under Creative Commons Attribution 4.0 International (CC BY 4.0) or similar

## Prohibited Sources
- Proprietary diagrams from commercial products without permission
- Screenshots from copyrighted materials
- Images from stock photo sites without proper licensing
- Any images without clear licensing information

## Creation Process

### 1. Planning Phase
- Determine the purpose of the diagram
- Identify the key concepts to illustrate
- Decide on the type of diagram (flowchart, architecture, process, etc.)
- Sketch a rough layout before creating the final version

### 2. Creation Phase
- Use AI generation tools with appropriate prompts
- OR create custom diagrams using tools like:
  - Draw.io (diagrams.net)
  - Mermaid (for flowcharts and diagrams in Markdown)
  - Inkscape (vector graphics)
  - GIMP (image editing)
- Ensure diagrams are clear, readable, and informative

### 3. Review Phase
- Verify the diagram accurately represents the concepts
- Check for proper labeling and legibility
- Confirm the diagram follows accessibility guidelines
- Ensure proper licensing and attribution

## Style Guidelines

### 1. Consistency
- Use consistent color schemes throughout the book
- Maintain similar font styles and sizes
- Follow a uniform approach to icons and symbols
- Align with the overall visual style of the book

### 2. Clarity
- Keep diagrams simple and uncluttered
- Use clear, readable fonts
- Ensure sufficient contrast for accessibility
- Include legends when necessary

### 3. Accessibility
- Provide alt text for all diagrams
- Use colorblind-friendly palettes
- Include descriptive captions
- Consider screen reader compatibility

## File Format and Naming

### 1. Formats
- Prefer SVG for vector diagrams (scalable and crisp)
- Use PNG for raster images (high quality, compressed)
- Avoid proprietary formats

### 2. Naming Convention
- Use descriptive, lowercase names with hyphens
- Include the module and concept in the name
- Examples:
  - `vla-pipeline-architecture.svg`
  - `ros2-action-server-flow.png`
  - `isaac-sim-environment-setup.svg`

## Licensing and Attribution

### 1. AI-Generated Images
- Include a note indicating the image was AI-generated
- Specify the tool used (e.g., "Image generated with DALL-E")
- If using prompts that build on training data, acknowledge that appropriately

### 2. Open-Source Images
- Include full attribution to the original creator
- Specify the license under which it's being used
- Link to the original source when possible

### 3. Custom Images
- Include a note that the image was created specifically for this book
- Specify the license under which it's being released

## Quality Standards
- All diagrams must be high resolution and clear
- Text must be readable at standard zoom levels
- Colors must be distinguishable by colorblind users
- File sizes should be optimized for web delivery
- All diagrams must have descriptive alt text

## Approval Process
1. Diagram is created following the guidelines
2. Diagram is reviewed for technical accuracy
3. Licensing and attribution are verified
4. Accessibility requirements are confirmed
5. Diagram is approved for inclusion in the book
